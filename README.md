# המקרר המשותף

אפליקציית ווב (PWA) לטאבלט משותף: כל אחד בוחר את השם שלו, מוסיף מאכלים עם תאריך תפוגה, מוחק מה שנגמר, ורואה בתצוגת "כל המקרר" את המאכלים של כולם מהתוקף הישן לחדש. כשמאכל פג תוקף האפליקציה מציגה באנר אדום בראש המסך ומספר אדום על הלשונית "כל המקרר". אין התרעות מערכת למכשיר.

## קבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | האפליקציה כולה (עיצוב + לוגיקה) |
| `manifest.json` | מאפשר "הוספה למסך הבית" עם שם ואייקון |
| `sw.js` | עבודה בלי אינטרנט |
| `icon-192.png`, `icon-512.png` | אייקונים |
| `serve.ps1` | שרת קטן לבדיקה ברשת הביתית |

| `firebase-config.js` | חיבור אופציונלי למאגר משותף בין כמה מכשירים (ראו למטה) |

בלי הגדרת Firebase הנתונים נשמרים בזיכרון הדפדפן של הטאבלט עצמו (localStorage). אין שרת ואין חשבונות.

## סנכרון בין כמה טאבלטים (Firebase)

עם Firebase כל המכשירים שפותחים את האפליקציה רואים את אותה רשימה, והשינויים מופיעים בזמן אמת. התכנית החינמית מספיקה בהרבה. ההגדרה חד־פעמית:

1. נכנסים ל-https://console.firebase.google.com עם חשבון Google ולוחצים **Create a project**. נותנים שם (למשל `mekarer`), מכבים את Google Analytics (לא נחוץ) ומסיימים.
2. במסך הפרויקט לוחצים על האייקון **`</>`** (Web) כדי להוסיף אפליקציית ווב. נותנים כינוי, לא מסמנים Firebase Hosting, ולוחצים **Register app**. מופיע קטע קוד עם `const firebaseConfig = { ... };`. משאירים את החלון פתוח.
3. פותחים במחשב את הקובץ `firebase-config.js` בפנקס הרשימות, מדביקים את הקטע `const firebaseConfig = { ... };` מתחת להוראות, ושומרים. אם סגרתם את החלון, הקטע נמצא תמיד ב-**Project settings ← Your apps ← SDK setup and configuration ← Config**.
4. בתפריט הצד ב-Firebase: **Build ← Firestore Database ← Create database**. בוחרים מיקום קרוב (למשל `europe-west1`), בוחרים **Start in production mode** ולוחצים Create.
5. בלשונית **Rules** מחליפים את כל התוכן בזה ולוחצים **Publish**:
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /items/{id} {
         allow read, write: if true;
       }
     }
   }
   ```
   זה מאפשר קריאה וכתיבה לרשימת המאכלים בלבד, לכל מי שיש לו את כתובת האפליקציה. לרשימת מקרר ביתית זה סביר. שאר המסד נשאר חסום.
6. מעלים מחדש ל-GitHub Pages את `firebase-config.js` המעודכן (ואת `index.html` ו-`sw.js` אם עדיין לא). אחרי דקה פותחים את האפליקציה בטאבלטים. בפינת הכותרת יופיע התג הירוק **"מסונכרן בין המכשירים"**.

מה קורה בפועל:
- הרשימה נשמרת בענן, וכל מכשיר מקבל עדכון ברגע שמכשיר אחר מוסיף או מוחק.
- בלי אינטרנט האפליקציה ממשיכה לעבוד על העותק המקומי (תג כתום "ממתין לחיבור"). השינויים נשלחים כשהחיבור חוזר.
- השם שכל אחד בחר ("מי במקרר") נשאר מקומי לכל טאבלט, כמו לפני. רק המאכלים משותפים.
- אם הרשימה במכשיר כבר הכילה מאכלים לפני החיבור, הם נשארים רק במכשיר ההוא ולא מועתקים לענן. מוסיפים אותם מחדש פעם אחת.

## איך להעביר לטאבלט

**אפשרות א׳ (מומלץ): אחסון חינמי ב-GitHub Pages**
1. פותחים מאגר חדש ב-GitHub ומעלים אליו את כל הקבצים בתיקייה הזו.
2. ב-Settings → Pages בוחרים Branch: `main`, תיקייה `/ (root)` ושומרים.
3. אחרי דקה מקבלים כתובת `https://<שם>.github.io/<מאגר>/`. פותחים אותה בכרום בטאבלט.
4. בתפריט הדפדפן בוחרים **"הוספה למסך הבית" / "התקנת אפליקציה"**. האפליקציה תיפתח במסך מלא כמו אפליקציה רגילה.

כתובת `https` נדרשת כדי שההתקנה על מסך הבית תעבוד. זו הסיבה שזו הדרך המומלצת.

**אפשרות ב׳: ברשת הביתית בלבד (לבדיקה)**
```bash
powershell -ExecutionPolicy Bypass -File .\serve.ps1
```
הסקריפט מדפיס כתובת כמו `http://192.168.1.20:8080/`. פותחים אותה בטאבלט כשהמחשב דלוק.

## איך סימון פגי התוקף עובד

- בכל דקה, ובכל פעם שהאפליקציה חוזרת לחזית, נבדק מה פג תוקף.
- מאכל שתאריך התפוגה שלו עבר מסומן באדום, מופיע בבאנר אדום בראש המסך ונספר במספר האדום על הלשונית "כל המקרר".
- מאכל שפג היום מסומן בכתום ("פג תוקף היום"), ומאכל שפג בתוך יומיים מסומן "פג בקרוב".

## פריטי דוגמה

בפעם הראשונה מופיעים ארבעה פריטי דוגמה (מסומנים "דוגמה") כדי לראות איך זה נראה. כפתור **"הסר את פריטי הדוגמה"** בתחתית המסך מנקה אותם.
